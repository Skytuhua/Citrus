# Native actions and resident settings

Citrus accepts physical files and folders through the launcher's file/folder pickers, workspace drops, and the **Files** wheel. Folder selections offer Files only. Unavailable cloud placeholders are rejected. The default gesture keys are **Shift: Convert**, **Alt: Tools**, and **Ctrl: Files**. The Files mode retains the internal enum name `OperationMode.Actions`; this is an implementation name, not the label shown to users. Change key assignments in Settings; each mode must have a different key. Pausing gestures dismisses the wheel and leaves ordinary Explorer input available. The keyboard-accessible launcher operation picker offers the same actions.

- **Copy files** puts the entire selection on the Windows clipboard as physical file references with a `Preferred DropEffect` DWORD of 1 (Copy). Paste into Explorer to create copies.
- **Move originals…** asks for an explicit destination. Cancel changes nothing. A batch preflight rejects known name conflicts, duplicate target names, drive roots, and a folder selected with its own descendants. Windows Shell `IFileOperation` performs the move on an owned STA worker, including cross-volume folders. It uses `FOF_SILENT | FOF_RENAMEONCOLLISION | FOF_NOCONFIRMATION | FOF_NOCONFIRMMKDIR | FOF_NOERRORUI | FOFX_EARLYFAILURE` (`0x0010061C`). A conflict that appears after preflight is given a new name instead of being replaced; successful destination paths are reported. Shell failures can leave a partial batch: the error reports known completed destinations. The application never implements recursive copy/delete. Quit waits for the native operation and its COM cleanup to finish; it does not forcibly cancel an in-progress move.
- **Copy paths** puts the entire selection on the clipboard, separated by Windows CRLF newlines.
- **Reveal** asks Explorer to select every selected item with structured process arguments.
- **Open Terminal** opens each distinct containing folder (or the selected folder itself). Citrus tries the installed Windows Terminal app alias with `-d <folder>`. If it is absent or cannot start, it uses the installed Windows PowerShell with `-NoLogo -NoExit`, then `cmd.exe /D` if PowerShell is absent. Fallback shells inherit `WorkingDirectory`; paths are never interpolated into shell commands.
- **Float on shelf** adds every selected path to a topmost reference shelf without copying storage. Select items and drag them to Explorer with Copy semantics, or use Copy selected / Ctrl+C and paste. Delete / Remove references removes shelf entries only. Missing/unavailable entries are removed on refresh, every two seconds. Closing the shelf discards its references.

Settings are stored atomically in `%LOCALAPPDATA%\Citrus\settings.json`. Fresh installations default to **Light** theme, gestures enabled, reveal completed outputs disabled, and **launch at sign-in disabled**. Saved theme preferences remain in place. Only an explicit change to launch at sign-in writes/removes the `Citrus` value in `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`: `"<absolute executable>" --background`. Loading defaults does not register startup. Invalid settings use defaults and show a warning. Settings support Light, Dark, or System; Windows high contrast overrides the palette. Windows reduced motion disables the indeterminate progress animation, with status text still available. Wheel animation is gated by the reduced-motion preference, Windows client-area animation and high-contrast settings.

Closing Home hides it and keeps Citrus resident. Tray Open, Pause, Settings, and Quit are connected; double-click opens Home. A normal second launch opens the resident Home. `--background` launches quietly and does not reopen an already running instance. Quit stops observation, closes dialogs, cancels conversion/discovery work, waits for submitted actions/workers, removes the tray icon, stops the shelf refresh, and releases the instance.

## Installer and diagnostics contract

Default mutex: `Local\Citrus-{WindowsIdentity.GetCurrent().User.Value}-{Process.GetCurrentProcess().SessionId}`. The SID is the Windows user SID string and the session ID is its decimal Windows process session ID. The activation pipe is `Citrus-{SID}-{sessionId}-activate`; unlike the Local mutex namespace, pipes are machine-wide, so the explicit SID/session components are required. The pipe uses `PipeOptions.CurrentUserOnly`, a single-byte ASCII `A` activation request, and `K` acknowledgement. There is no remote quit command. Clients have a five-second deadline; server reads have a two-second deadline.

A per-user installer/uninstaller must acquire and hold ownership of this mutex on its installing thread before modifying files, then release ownership on that same thread afterward. Retaining an unowned mutex handle is insufficient: the app uses `WaitOne(0)`, not object existence, to decide ownership. For an existing object, a zero-time wait must acquire it (including abandoned ownership); timeout means the resident still owns it and the user must quit Citrus. This ownership contract supersedes any older existence-only installer guidance. Since installation files can be shared by several sessions of the same user, Task 8 must also guard other active sessions of that SID before replacement/removal. Do not kill arbitrary Citrus processes. Preserve settings on ordinary upgrade, and remove only Citrus's Run value on uninstall. The normal installer must not enable sign-in launch.

## Windows verification

Run `dotnet test tests/Citrus.Windows.Tests/Citrus.Windows.Tests.csproj -c Release --logger trx --blame-hang --blame-hang-timeout 2m` on Windows x64 with a usable interactive desktop/clipboard. The project reuses one nonparallel STA fixture; native lifecycle tests run a separate executable entry point in the test assembly with unique settings directories and instance GUIDs. Test startup writes use a disposable HKCU subtree. Child cleanup affects only PIDs created by the test.

Set `CITRUS_TEST_SECOND_VOLUME` to a writable directory on a different physical volume than the temporary source directory to enable the cross-volume Shell folder test. Without it that test is explicitly skipped/pending. Creating a drive-letter alias to the same volume is insufficient.

The initial implementation record described a Linux host that could not run native clipboard, Shell move, registry, WPF lifecycle or tray checks. That is historical host context. Consult the current [preview notes](PREVIEW-NOTES.md) for verification scope and outstanding qualification. Actual Explorer selection/terminal opening, shelf OLE mouse dragging, screen-reader focus order, physical mixed-DPI behavior, theme/high-contrast/reduced-motion inspection, session activation/focus and sign-in behavior need explicit Windows evidence. Passing source/core CI does not qualify those native workflows.
