Microsoft Visual C++ runtime libraries (proprietary redistributable)
The ten unmodified x64 CRT DLLs under feature-pack/libreoffice/System64 are
from the pinned official LibreOffice MSI. Their exact upstream hashes are in
feature-pack-runtime.sha256.json. Citrus also deploys identical app-local
copies beside Citrus.Windows.exe (including OCR natives) and the isolated
Office executables in feature-pack/libreoffice/program. These copies are
covered by Microsoft's separate software license terms; they are not MPL or
open-source Citrus components. The complete upstream Microsoft Visual C++
Runtime Libraries license is retained in feature-pack/libreoffice/license.txt.
No DLLs are copied from the user's Windows installation, no redistributable
installer runs, and no system PATH or machine runtime installation changes.
https://learn.microsoft.com/cpp/windows/redistributing-visual-cpp-files

DocumentFormat.OpenXml 3.5.1: MIT; Copyright Microsoft Corporation.
Tabula 1.0.1 / tabula-sharp: MIT; Copyright project contributors.
PdfPig 0.1.16: Apache-2.0; existing PDF notices remain applicable.

Exact asset versions, download URLs, SHA-256 digests and source inventory:
feature-pack.lock.json. Runtime inventory: feature-pack-runtime.sha256.json.
Acquisition and verification: build-feature-pack.ps1. Document parsing workers
run in a Windows AppContainer with no network capabilities and private job
staging. This implementation has no unrestricted execution fallback.
The trusted office-worker.py binding is Citrus source under the repository's
MIT license. Preserve that license with the application. Its SHA-256 is pinned
in both the feature-pack lock and runtime catalog; build verification checks
the worker as well as all upstream binary and source artifacts.

The worker initializes the pinned LibreOfficeKit library. Calc uses hidden
in-process UNO; Impress schedules its hidden export on Office's main loop.
Neither path uses a network listener or an out-of-process UNO bridge. Windows
AppContainer and Job Object ownership cover the entire native process tree.

PDF reconstruction is best effort. It does not recover original Office
formulas, proprietary fonts, arbitrary handwriting or perfect page semantics.
OCR data is English. Mixed raster text is reconstructed where recoverable;
artwork inside a replaced scanned region may need manual restoration.
DOCX output marked Pages compatible is a genuine DOCX file, not a .pages file.
